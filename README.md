# אדמה – מאגר השידוכים לחוות גבעות

מערכת CRM לניהול שידוכים, בעברית מלאה, מותאמת 100% למובייל.

## מערכת עצמאית לחלוטין

המערכת הזו עומדת בפני עצמה ואינה חולקת שום נתון עם אף מערכת אחרת.
יש לה פרויקט Firebase משלה בלבד, והחיבור אליו מוגדר במקום אחד יחיד: `lib/appConfig.js`.

## מה יש במערכת

- **מאגר מועמדים ומועמדות** – כרטיס מקוצר וכרטיס מלא, סינון מתקדם, סרגל תוויות, מעבר בין מאגר בנים למאגר בנות, ומועדפים אישיים לכל אשת צוות.
- **הוספה ועריכה של כרטיס** – טופס הוספה מלא, מסך עריכה, כמה תמונות למועמד/ת, והקלטות שמע.
- **הצעות שידוך** – מעקב לפי שלבים, כולל אשף התאמה.
- **משימות צוות** – משימות עם תאריך יעד ושיוך לאשת צוות.
- **כספים ותשלומים** – סוגי שירות, חיובים ומעקב, בהרשאת מנהלת בלבד.
- **ייצוא** – הפקת קובץ PDF מעוצב בעברית לכרטיס מועמד/ת.
- **טיפים לצוות, התראות והגדרות**.
- **קישור זמינות למועמד/ת** – עמוד `/status` לעדכון זמינות בלי כניסה למערכת ובלי חשיפת פרטים.
- **שאלון היכרות** – טופס למועמד/ת ומסך ניהול נלווה.

## הרשאות וכניסה

- הכניסה למערכת היא **כניסה אישית עם חשבון Google** בלבד.
- רשימת אנשי הצוות מנוהלת מתוך המערכת ונשמרת במסד הנתונים. היא מתחילה ריקה.
- שתי רמות הרשאה: **מנהלת** (רואה הכל, כולל כספים) ו**נציגה**.
- **חסימת מועמד/ת מנציגה מסוימת** – נאכפת גם בכללי האבטחה של מסד הנתונים, לא רק במסך.
- **המנהלת הראשונה** מוגדרת ב-`lib/appConfig.js` ומזוהה כמנהלת גם כשרשימת הצוות ריקה – אחרת אי אפשר היה להיכנס למערכת חדשה כדי להוסיף אליה את שאר הצוות.

## הקמה

1. ליצור פרויקט Firebase חדש ונפרד, ובתוכו להפעיל **Firestore** ו-**Authentication** עם ספק **Google**.
2. להעתיק את פרטי החיבור של הפרויקט אל `lib/appConfig.js`.
3. להעלות את תוכן `firestore.rules` לכללי האבטחה של Firestore.
4. להוסיף את כתובת האתר לרשימת הדומיינים המורשים ב-Authentication.

## הרצה מקומית

```bash
npm install
npm run dev
```
